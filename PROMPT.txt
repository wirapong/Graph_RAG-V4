Claude Code Prompt: AI Metadata Automation with Knowledge Graphs for Github repo and ready to deploy to streamlit.app
PHASE 1 — Project Scaffold
Build a Python project scaffold for an AI Metadata Automation system using Knowledge Graphs.

Structure:
metadata_kg/
├── core/
│   ├── kg_builder.py        # Knowledge Graph construction
│   ├── llm_agent.py         # LLM-as-Agent orchestrator
│   └── metadata_schema.py   # DCAT2/DCMI-aligned schema
├── pipeline/
│   ├── ingest.py            # Raw data ingestion
│   ├── extract.py           # LLM-based entity/metadata extraction
│   ├── validate.py          # KG-based consistency validation
│   └── lifecycle.py         # Metadata lifecycle manager (4 phases)
├── governance/
│   ├── lineage.py           # Data lineage tracker
│   ├── policy.py            # Policy-as-code enforcement (GDPR)
│   └── xai.py               # Explainability layer
├── search/
│   └── semantic_search.py   # NLP/NLU semantic search engine
├── api/
│   └── routes.py            # REST API endpoints
└── tests/
└── .streamlit/
    ├── config.toml
    └── secrets.toml.example

Use: Python 3.11, rdflib, networkx, langchain, fastapi, pydantic v2

PHASE 2 — Knowledge Graph Core
In metadata_kg/core/kg_builder.py, implement:

1. Class `MetadataKnowledgeGraph` using rdflib + networkx:
   - add_entity(id, type, properties: dict)
   - add_relation(subject, predicate, object)
   - validate_consistency() → returns list of conflicts
   - export_to_turtle() → .ttl file
   - to_networkx() → for GNN downstream use

2. Schema alignment:
   - Map all entities to DCAT 2 / DCMI terms
   - Support custom domain extensions (finance, health)

3. Cross-domain linking:
   - link_cross_domain(graph_a, graph_b, shared_key)
   → returns merged subgraph of overlapping concepts

PHASE 3 — LLM-as-Agent
In metadata_kg/core/llm_agent.py, implement an LLM-as-Agent using LangChain:

Tools the agent must be able to call:
- extract_entities(text) → list[Entity]
- map_schema(raw_fields, target_schema) → mapped_dict
- validate_via_kg(entity_id) → bool + reason
- flag_hallucination(claim, kg_context) → confidence_score

Agent behavior:
- Accept raw document or API payload as input
- Auto-plan: extract → map → validate → store
- On low confidence (<0.7): trigger Human-in-the-loop flag
- Log each reasoning step for XAI traceability

Use: langchain AgentExecutor, Claude claude-sonnet-4-20250514 as base LLM

PHASE 4 — Metadata Lifecycle Pipeline
In metadata_kg/pipeline/lifecycle.py, implement MetadataLifecycle with 4 phases:

Phase 1 — Creation:
  - LLM extracts metadata from raw input
  - Auto-tag with DCAT2 vocabulary

Phase 2 — Cleaning:
  - Deduplicate using KG similarity (cosine on embeddings)
  - Flag missing mandatory fields
  - AI-suggested corrections with confidence score

Phase 3 — Maintenance:
  - Incremental update without full retraining (continual learning stub)
  - Version-stamp each change with timestamp + agent_id

Phase 4 — Retirement:
  - Archive policy: move to cold storage after N days unused
  - GDPR deletion handler: purge_entity(id, reason)

Each phase must emit lifecycle_event → lineage.py

PHASE 5 — Governance & Explainability
In metadata_kg/governance/:

1. lineage.py — DataLineage class:
   - record_event(entity_id, action, agent, timestamp)
   - get_provenance_chain(entity_id) → ordered list of events
   - export_lineage_graph() → JSON-LD format

2. policy.py — PolicyEngine class:
   - load_rules(rules_file: yaml)
   - check_compliance(metadata_dict) → pass/fail + violated_rules
   - Built-in rules: GDPR fields, mandatory DCAT fields, PII detection

3. xai.py — ExplainabilityLayer class:
   - explain_decision(entity_id) → human-readable string
     (pulls from KG lineage + agent reasoning log)
   - confidence_report(entity_id) → dict with score per field

PHASE 6 — Semantic Search
In metadata_kg/search/semantic_search.py, implement:

Class `SemanticMetadataSearch`:
- index_kg(kg: MetadataKnowledgeGraph)
  → embed all nodes using sentence-transformers
- search(query: str, top_k=10) → ranked list of entities
  → use cosine similarity on embeddings
- keyword_fallback(query: str) → BM25-based results
- hybrid_search(query: str) → merge semantic + keyword results

NLU enhancement:
- expand_query(query) → synonyms + related KG concepts
- explain_result(entity_id, query) → why this result matched

PHASE 7 — API & Human-in-the-Loop
In metadata_kg/api/routes.py, build FastAPI endpoints:

POST   /ingest          — submit raw document for metadata extraction
GET    /metadata/{id}   — retrieve metadata + provenance chain
GET    /search          — semantic search (query param)
POST   /validate/{id}   — trigger KG consistency check
GET    /explain/{id}    — XAI explanation for entity
POST   /hitl/review     — human expert submits correction/approval
GET    /hitl/queue      — list items flagged for human review
POST   /policy/check    — run policy compliance on metadata payload

All endpoints return: { data, confidence, lineage_url, warnings[] }

PHASE 8 — Tests & Benchmarking

1. test_kg_builder.py

2. test_llm_agent.py

3. test_lifecycle.py

4. test_governance.py

5. benchmark.py

   - output: benchmark_report.json
